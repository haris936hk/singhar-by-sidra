## Context

The storefront is a TypeScript Shopify Hydrogen application using React Router, MiniOxygen, Vite, and Tailwind CSS v4. The root loader already separates critical and deferred work, while `shouldRevalidate` currently avoids root-loader requests during ordinary navigations. The homepage route owns a hard-coded hero and editorial promotional section that can serve as reliable fallback UI.

The BILDIT Hydrogen example uses `@bildit-platform/hydrogen` to fetch scheduled content from the server, provide it to `BilditRoot`, and render it at `SlotPlaceholder` locations. The current project has no BILDIT dependency, slots, editor bridge, or BILDIT CSP directives. The configured BILDIT base URL is `https://admin.bildit.co`; its API key remains a server runtime secret.

## Goals / Non-Goals

**Goals:**

- Render BILDIT scheduled content in the homepage hero and promotional placements.
- Keep the existing homepage experience as the fallback when BILDIT is empty or unavailable.
- Support BILDIT location and preview-date matching for `/`.
- Enable the BILDIT Visual Editor bridge without manually injecting a CMS script before hydration.
- Keep credentials server-side and preserve Shopify commerce behavior.
- Make navigation into and away from the homepage refresh the root BILDIT data without revalidating the root loader for unrelated route-to-route navigation.

**Non-Goals:**

- Replacing Shopify catalog, cart, checkout, customer accounts, or analytics with BILDIT.
- Making every route CMS-managed in this change.
- Moving the full homepage layout into BILDIT or creating a general page-builder abstraction.
- Adding BILDIT content to the header, footer, product pages, or collection pages.
- Creating or managing BILDIT accounts, API keys, scheduled content, or Oxygen environments in application code.

## Decisions

### Use the BILDIT Hydrogen adapter and the existing root loader

The root loader will call BILDIT's request-aware server helper with the incoming request and `context.env`. This keeps the API key on the server, lets BILDIT match the `/` location and preview date, and follows the existing critical/deferred loader boundary. BILDIT's empty or failed response will be treated as an empty banner set, allowing the homepage fallback to render.

The alternative of fetching BILDIT from the browser is rejected because it would expose credentials, duplicate server-owned data loading, and make initial rendering and preview matching less reliable.

### Wrap the existing application at the root

`BilditRoot` will wrap the existing analytics provider, page layout, and route outlet. This makes the BILDIT context available to homepage slots while preserving the current `PageLayout` composition and Shopify analytics provider.

The client entry will initialize BILDIT's host React globals and CMS dependency registry before `hydrateRoot`. The built-in Hydrogen dependency map will be used initially; extra modules will only be registered if an authored banner requires them. The Hydrogen bundled admin script supplied by the adapter will be used for the Visual Editor. No `cms-client` script or custom `INJECT_SCRIPT` listener will be added to the document head.

### Replace selected homepage boundaries with slots and fallbacks

The current hero will become the fallback for `home-hero`, and the current editorial banner will become the fallback for `home-promo`. The slot IDs are stable CMS contracts and must be used when scheduled content is created in BILDIT.

Other homepage sections remain ordinary Hydrogen components. This limits the initial blast radius and lets the marketing team control campaigns without allowing a CMS configuration mistake to remove the store's primary navigation or commerce content.

### Merge BILDIT CSP directives instead of replacing Hydrogen CSP

The existing Shopify CSP generated by Hydrogen will be extended with BILDIT's directives and the response header will be passed through `allowBilditIframeEmbedding`. The configuration will preserve Shopify and self-hosted sources while allowing the BILDIT CDN, required editor workers, and the Tailwind browser runtime used by draft content.

The documented Live Editor requirements for `unsafe-eval`, `blob:`, and BILDIT's iframe ancestors will be accepted only in the scoped CSP directives needed by the adapter. A manual script tag is rejected because it races hydration and is explicitly rejected by BILDIT Verify.

### Keep homepage revalidation targeted

The current root optimization will remain for unrelated route transitions. Root data will revalidate when either the current or next pathname is `/`, including homepage query-string changes. This ensures that:

- A shopper navigating from a product or collection page to `/` receives the homepage's BILDIT banners.
- Leaving `/` clears the homepage banner set instead of retaining it in the provider.
- Preview-date query changes on `/` fetch the appropriate banner set.

Revalidating every route transition is rejected because it would add BILDIT and root data work to routes outside this change.

### Use environment-specific server configuration

Local MiniOxygen will read `BILDIT_API_URL` and `BILDIT_API_KEY` from the ignored `.env` file. Oxygen will receive the same variable names as secret environment values in the appropriate deployment environment. The application will not use `PUBLIC_` names for these values, include them in loader data, or send them to the browser.

The BILDIT URL will remain the root CMS host, such as `https://admin.bildit.co`; the adapter appends its remote banner endpoint. No custom API client or direct browser request will be introduced.

### Bundle BILDIT packages for Oxygen SSR

Vite SSR configuration will explicitly avoid externalizing the BILDIT adapter, its rendering core, and the rendering dependencies identified by the reference implementation. This keeps the dynamic banner renderer compatible with the Oxygen bundle and avoids CJS/ESM or duplicate React resolution failures.

## Risks / Trade-offs

- [BILDIT API failure or invalid configuration] -> The adapter returns an empty banner set, the homepage keeps its existing fallback UI, and server logs retain the diagnostic without exposing the key.
- [Wrong BILDIT location or slot ID] -> No CMS content appears; the fallback remains visible. The implementation tasks will include a dashboard content checklist using `/`, `home-hero`, and `home-promo`.
- [Root revalidation adds work on homepage transitions] -> Revalidation is limited to navigations entering, leaving, or changing the homepage, while Shopify menu data remains cacheable.
- [Visual Editor CSP broadens iframe and script permissions] -> Merge only the documented BILDIT directives, preserve Shopify defaults, and validate both normal storefront responses and the editor handshake.
- [Tailwind browser runtime adds a third-party script and editor-only execution requirements] -> Use the nonce supplied by Hydrogen, allow only the documented CDN in CSP, and verify that the public storefront still loads without editor interaction.
- [CMS-authored code imports an unregistered module] -> Start with Hydrogen-native dependencies only and document that any additional banner import must be explicitly registered before publishing.
- [BILDIT plan or publishing entitlement prevents live rendering] -> Test the configured key with a published scheduled item after integration; distinguish an entitlement issue from application failures by checking the server response and Visual Editor behavior separately.

## Migration Plan

1. Install the BILDIT Hydrogen adapter and update the npm lockfile.
2. Add the server loader, root provider, client bootstrap, CSP merge, SSR bundling configuration, and homepage slot fallbacks.
3. Run type generation, typecheck, lint, and production build validation.
4. Start MiniOxygen with the already configured local BILDIT variables and confirm the homepage still renders when no content is scheduled.
5. Create one published BILDIT item at location `/` using `home-hero`, then verify normal rendering and the Visual Editor.
6. Configure matching secret variables in the intended Oxygen environment and redeploy.
7. Validate the production homepage and BILDIT Verify flow before adding additional campaigns.

If the deployment must be rolled back, deploy the previous Hydrogen build. The existing homepage fallbacks make disabling BILDIT content safe; removing the environment variables alone will also result in empty BILDIT content and fallback rendering, but does not remove the editor CSP or dependency code.
